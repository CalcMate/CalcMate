## 3. 계산식 검증 + 계산 순서

### 현재 DB formula
```json
{
  "national_pension": "monthly_salary*0.045",
  "health_insurance": "monthly_salary*0.03545",
  "employment_insurance": "monthly_salary*0.009",
  "total": "monthly_salary*(0.045+0.03545+0.009)"
}
```

### FI-1: 장기요양보험 계산 순서 (Critical)
올바른 순서:
1. `health_insurance = monthly_salary × 0.03545`
2. `long_term_care = health_insurance × 0.1296`  ← **반드시 건강보험료에 곱해야 함**

잘못된 순서 (구현 시 흔한 오류):
- `long_term_care = monthly_salary × 0.1296` → 급여에 직접 곱하면 3,000,000 × 0.1296 = **388,800원** (실제 13,783원 대비 375,017원 과다 오류)

현재 상태: 장기요양보험 변수 자체 없음 → 미구현.

| 케이스 | 월급여 | 현재 NP | 올바른 NP | 현재 total | 올바른 total | 오차 |
|---|---|---|---|---|---|---|
| 하한 미만 | 200,000 | 9,000 | **17,550** (하한 적용) | 17,890 | 27,359 | -9,469 |

## 5. 경계값 3점 세트

### 국민연금 기준소득월액
| 급여 | 현재 NP | 올바른 NP | 차이 | 판정 |
|---|---|---|---|---|
| 389,999원 (하한-1) | 17,549.955 ≈ 17,550 | 390,000 × 4.5% = **17,550** | ~0 | ⚠️ 우연 일치 |
| 390,000원 (하한) | 17,550 | 17,550 | 0 | OK |
| 390,001원 (하한+1) | 17,550.045 ≈ 17,550 | 17,550 | ~0 | ⚠️ 우연 일치 |
| 6,169,999원 (상한-1) | 277,649.955 ≈ 277,650 | 277,650 | ~0 | ⚠️ 우연 일치 |
| 6,170,000원 (상한) | 277,650 | 277,650 | 0 | OK |
| 6,170,001원 (상한+1) | 277,650.045 ≈ 277,650 | 277,650 | ~0 | ⚠️ 우연 일치 |

> "우연 일치": 경계 ±1원에서 차이가 0.045원에 불과해 반올림 후 구별 불가.
> 경계에서 멀어질수록 오차 급증 — 200,000원 입력 시 현재=9,000원, 올바=17,550원 (8,550원 오차).
> **FI-2는 경계값이 아닌 경계 바깥(예: 20만원, 1000만원)에서 오류가 드러남.**

## 7. 공통 패턴 vs 4대보험 전용 분류

**공통 패턴 재사용 가능:**
- FI-4: `compute_rules.positive_inputs` (이미 주휴수당에서 사용 중) 또는 unemployment-benefit 방식
- FI-2: min/max 클램프 — unemployment-benefit `min(max(salary, NP_MIN), NP_MAX)` 동일 구조
- FI-8: _formula 반환 — 모든 계산기에서 동일
- FI-9: out.notices 배열 — 퇴직금/실업급여 동일
- FI-10: legal_basis `insurance_rates` 섹션 추가 (unemployment-benefit benefit_amounts와 동일 구조)

**4대보험 전용:**
- FI-1: 장기요양보험 = `health_insurance × ltc_rate` — 2단계 계산 (다른 계산기와 구조 다름)
- FI-5: 산재보험 안내 — 콘텐츠 전용
- FI-6/7: FAQ 예시/부담 비율 오류 — 콘텐츠 전용

## 8. 수정 방향 제안

### Phase 1 (로직)
1. `legal_basis.draft.yaml` four-insurances에 `insurance_rates` 섹션 추가:
   - NP_RATE=0.045, NP_MIN=390000, NP_MAX=6170000
   - HI_RATE=0.03545, LTC_RATE=0.1296, EI_RATE=0.009
2. `app_generator._compute_js()`에 `slug=="four-insurances"` 분기 추가:
   - 입력 검증 (monthly_salary ≤ 0 → null)
   - 국민연금: `clamp(salary, NP_MIN, NP_MAX) × NP_RATE`
   - 건강보험: `salary × HI_RATE`
   - **장기요양보험: `health_insurance × LTC_RATE`** (건강보험료에 곱)
   - 고용보험: `salary × EI_RATE`
   - total: 4종 합산
   - notices: 상한/하한 클램프 적용 시 안내
   - _formula: 케이스별 단계 표시
3. out_schema에 `long_term_care` 추가

### Phase 2 (콘텐츠)
1. faq[2]: 건강보험 예시 106,500 → 106,350원 + 장기요양보험 예시 추가
2. faq[3]: 고용보험 부담 비율 교정 (근로자 0.9%, 사업주 0.9%+)
3. 산재보험 안내 문구 추가 (사업주 전액 부담, 근로자 공제 없음)
4. total 예시 금액 갱신 (장기요양 포함)
5. DB formula 갱신 (장기요양 추가)
