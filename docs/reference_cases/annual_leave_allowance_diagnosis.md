## 1. 설계 범위 확정 (최우선)

### 현재 이 계산기가 다루는 개념

연차 세 개념 중 **"미사용 연차수당 대상 연차"** 금액 산정:

| 개념 | 설명 | 이 계산기 |
|------|------|-----------|
| 발생 연차 | 근속연수 기반 법적 발생량 (제60조) | ❌ 미구현 |
| 사용 가능 연차 | 발생분 - 이미 사용분 | ❌ 미구현 |
| 미사용 수당 대상 연차 | 정산 대상 미사용분 | ✅ 사용자 직접 입력 |

**결론**: 이 계산기는 "**미사용 연차수당 금액 계산기**" — 사용자가 미사용 연차 일수와 1일 통상임금을 직접 입력하면 수당 금액을 반환한다. 연차 발생 개수 계산이나 사용 이력 입력 기능은 없다.

**설계 목적**: 퇴직 정산 또는 연간 미사용 연차 정산 모두 해당 가능 (용도를 명확히 구분하지 않음).

### 통상임금 구성

입력 방식: **사용자가 1일 통상임금(`daily_wage`)을 직접 입력** — 시스템이 산정하지 않음.

단, faq[3]에서 "기본 일급만 기준으로" 라고 설명하는 것은 **잘못됨** → AL-2 참조.

## 2. 통상임금 구성 확인 (신규)

- **현재 방식**: 사용자가 `daily_wage` 직접 입력
- **faq[3] 오류**: "연차수당은 기본 일급만 기준으로 하므로"
- **법적 기준**: 연차수당은 **통상임금** 기준 (근로기준법 제2조제1항제5호, 시행령 제6조)
  - 통상임금 = 기본급 + 정기적·일률적·고정적으로 지급되는 수당 (직책수당, 가족수당 중 전원지급분 등)
  - 복리후생비 성격(식비 중 일부 등)은 포함 여부 별도 판단
- **영향**: 사용자가 "기본급만" 계산 → 실제 받아야 할 수당보다 과소 청구

## 3. 입력값 검증

**현재 상태**: 완전히 없음.

| 입력 | 현재 처리 | 올바른 처리 |
|------|-----------|-------------|
| `daily_wage ≤ 0` | 0원 정상 표시 (alert 없음) | `return null` |
| `daily_wage < 0` | 음수 결과 표시 ❌ | `return null` |
| `unused_days ≤ 0` | 0원 정상 표시 (alert 없음) | `return null` |

- 기존 패턴 재사용 가능: weekly-holiday-allowance, severance-pay 동일 패턴 (`if (x <= 0) return null`)

## 4. 계산식 검증 (근로기준법 제60조제5항)

**formula**: `daily_wage * unused_days`

법적 근거: 미사용 유급휴가에 대해 통상임금 기준으로 지급 → **수학적으로 정확**.

| 8만원 × 4일 | 320,000원 | 320,000원 | ✅ |

## 6. 반올림 방식

`daily_wage * unused_days` — 정수 × 정수 → 소수점 발생 없음.
시급 기반으로 일급 환산 시에는 소수점 발생 가능하나 현재 계산기 설계 범위 밖.

**현재 상태**: 이슈 없음.

## 7. 정부 기준 대조 + 계산기 비교 3건

| 케이스 | 정부 기준 | 계산기 | 판정 |
|--------|-----------|--------|------|
| ① 1년 미만 (5일 미사용, 일급 10만원) | 50만원 | 50만원 | ✅ |
| ② 5년차 (17일 기준, 일급 10만원) | 연차 17일 → 170만원 | 직접 입력 방식 — 17 입력 시 170만원 | ✅ (입력 의존) |
| ③ 21년차 (25일 상한, 일급 10만원) | 25일 → 250만원 | 직접 입력 방식 — 25 입력 시 250만원 | ✅ (입력 의존) |

계산식 자체는 정확. 연차 개수 계산 없이 사용자 직접 입력이므로 "정부 계산기 비교"의 ②③은 입력이 올바르다는 전제하에 일치.

## 수정 방향 제안 (Phase 1~3 계획)

### Phase 2 (콘텐츠)

4. **AL-2**: faq[3] 교정 — "통상임금 = 기본급 + 고정수당 (직책수당 등)" 명시

### Phase 3 (UX)
