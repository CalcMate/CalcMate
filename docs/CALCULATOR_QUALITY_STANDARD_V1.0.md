## 체크리스트

### □ 1. 계산식 (Formula)
- [ ] 코드의 formula가 법령·정부 가이드 기준과 수학적으로 동일한가
- [ ] Python `formula_engine`과 JS `computeResult` 결과가 일치하는가 (부동소수점 포함)
- [ ] 계산식의 연산자 우선순위가 의도와 일치하는가 (괄호 명시 권장)

### □ 2. 법령 (Legal)
- [ ] `legal_basis.draft.yaml`에 해당 계산기 항목이 존재하는가
- [ ] 법령명·조항이 정확하며 현행 조문과 일치하는가
- [ ] **폐지된 조항을 인용하지 않는가** — `legal_basis.draft.yaml` `forbidden_articles` 기준으로 DB `faq` + `article_content` + 계산기 HTML(workspace) 전수 검색 (G8는 writer body_html만 검사 — DB 필드는 사각지대, #17)
- [ ] `writer_note`에 예외 조항(15시간 미만 / 1년 미만 등)이 명시되어 있는가

### □ 3. 경계값 (Boundary)
- [ ] 법적 지급 기준 경계 **직전/기준점/직후** 3점 세트 테스트 완료
  - 주휴수당: 14.99 / 15.00 / 15.01시간
  - 퇴직금: 364 / 365 / 366일 (1년 미만 = 0원 + 법령 안내)
  - 연차수당: 0 / 1 / 2개 미사용 연차
- [ ] 경계 미만 입력 시 계산기가 0원 반환 또는 명확한 안내를 표시하는가
  - 경계 미만 케이스: 주휴수당(15시간 미만), 퇴직금(1년 미만), 실업급여(180일 미만 피보험 단위기간)
- [ ] 경계 이상 입력 시 올바른 결과를 반환하는가

### □ 4. 예외 처리 (Edge Cases)
- [ ] 음수 입력 → 오류 처리 (결과 미표시 또는 경고)
- [ ] 0 입력 → 오류 처리 (0이 유효한 케이스인지 명확히)
- [ ] 비현실적 극단값 (시급 1,000,000원, 근무 168시간 등) → 경고 또는 상한 제한
- [ ] 법적 지급 제외 대상(15시간 미만 등) → 0 반환 + 설명 문구

### □ 5. UI (User Interface)
- [ ] 계산 결과값이 표시되는가 (`result-card` 노출)
- [ ] 계산 과정이 표시되는가 (`out._formula` 반환 권장)
  - 예: "10,000원 × (40÷40×8) = 80,000원"
- [ ] 입력값이 상세 카드에 나열되는가 (`detail-rows`)
- [ ] 법령 출처가 계산기 HTML에 표시되는가
- [ ] 공식(formula) 코드 표기가 있는가

### □ 6. SEO 정합성 (SEO Consistency)
- [ ] SEO 글 예시 금액 ① = 계산기 실제 결과 ②
  - 동일 입력(시급, 시간 등)으로 계산기 직접 계산 후 교차 확인
- [ ] SEO 글 계산 공식 설명 = 실제 formula 로직
- [ ] FAQ 금액 예시 = 계산기 결과
- [ ] "주 15시간 미만 미지급" 등 예외 조건이 SEO 글과 계산기 동작 모두에 반영되는가

### □ 7. FAQ
- [ ] 최소 5문항 이상 (G3 gate 기준)
- [ ] 구체적 수치/조건 포함 (단순 "네/아니오" 지양)
- [ ] 법령 조항 최소 1회 언급
- [ ] 지급 제외 케이스 FAQ 포함
- [ ] **권리·의무 안내가 정확한가** — 법적 의무를 임의사항처럼, 또는 권리를 제한사항처럼 표현하지 않았는가
- [ ] **계산 기준 설명이 법적 정의와 일치하는가** — 예: 연차수당 기준 "기본급"(❌) vs "통상임금"(✅)

### □ 8. 예시 계산 (Examples)
- [ ] 계산 예시 최소 2개 (G4 gate 기준)
- [ ] 서로 다른 조건으로 구성 (동일 조건 반복 금지)
- [ ] 예시 결과값이 실제 계산기 formula로 검증 가능한가
- [ ] 만원 단위 예시 사용 시 계산 결과와 정확히 일치하는가

### □ 9. 반올림 (Rounding)
- [ ] 원 단위 미만 처리 방식 명시 (절사/반올림/절상)
- [ ] Python 계산(`formula_engine`)과 JS 계산(`computeResult`)의 반올림 방식이 일치하는가
- [ ] UI 표시(`Math.round`) 방식이 계산 결과와 일치하는가

### □ 10. 테스트 케이스 (Test Cases)
- [ ] 법적 경계값 3점 세트 단위 테스트 작성
- [ ] 음수/0/극단값 입력 테스트 작성
- [ ] SEO 글 예시 금액 교차 검증 테스트

### □ 11. 발생 기준과 사용 가능 기준 혼동 여부 (발생형 계산기)
- [ ] 계산기가 다루는 개념을 명확히 규정했는가 — "발생 연차 / 사용 가능 연차 / 미사용 수당 대상 연차" 中 어느 것인가
- [ ] 사용 이력(이미 사용한 연차)을 입력받는가, 사용자가 직접 미사용분을 입력하는가
- [ ] 퇴직 시 정산인지 연간 정산인지 설계 목적이 명시되어 있는가
- [ ] FAQ/콘텐츠의 설명이 실제 계산기 설계 범위와 일치하는가

### □ 12. 계단형 규칙 전 구간 정확성
- [ ] 계단형 가산 규칙(연차, 퇴직금 등)이 전 구간에서 정확히 구현되는가
- [ ] **상한 도달 이후 정체 구간** (예: 21년차 25일 → 22년차도 25일 유지)이 올바르게 처리되는가
- [ ] 경계 3점 테스트 외에 상한 근처 극단값 2년 이상 연속 구간 테스트가 있는가

## 심각도 기준

| 등급 | 기준 | 예시 |
|------|------|------|
| **critical** | 잘못된 법적 판단을 정상 결과처럼 표시 | 주 14시간 입력 → 주휴수당 28,000원 표시 |
| **major** | 유효하지 않은 입력에 경고 없이 결과 표시 | 음수 시급 → 음수 결과 표시 |
| **minor** | UX 품질 문제, 법적 영향 없음 | 계산 과정 미표시, 비현실적 상한 없음 |

### 권리·의무 안내 오류 (Critical급 준용)

계산 결과가 수학적으로 정확하더라도, 법적 권리·지급 의무·수령 자격 등을 잘못 안내하여 사용자가 권리를 포기하거나 경제적 손실을 입을 가능성이 있는 경우, **Critical에 준하는 우선순위**로 즉시 처리한다.

**적용 예시**:
- "퇴직 후 미사용 연차는 지급 안 될 수 있다" → 의무 지급 원칙을 임의사항처럼 안내 (AL-3)
- "기본 일급만 기준" → 통상임금에 고정수당 포함됨을 누락하여 과소 청구 유발 (AL-2)
- "최대 300일 수령 가능" → 실제 120~270일로 과대 안내 (UB-2)

**판단 기준**: 사용자가 해당 안내를 믿고 권리 행사를 포기하거나 경제적 손실이 발생하는가?
