### 3. 계산 공식

#### 공식 출처

- **전월세전환율 기반 전세↔월세 환산 공식**: 주택임대차보호법 제7조의2 + 시행령 제9조, 한국부동산원 LH 임대차분쟁조정위원회 공식 계산기(adrhome.reb.or.kr) 사용 공식과 동일

#### 확정 공식 (만원 단위, rate는 % 연율)

```
① 전세 월 기회비용 (jeonse_opp_cost)
   = (전세보증금 - 월세보증금) × 전환율 / 100 / 12
   = (jeonse_deposit - wolse_deposit) * rate / 100 / 12

② 월세→전세 환산금액 (wolse_to_jeonse_equiv)
   = 월세보증금 + (월세금액 × 12 / (전환율 / 100))
   = wolse_deposit + wolse_amount * 1200 / rate

③ 월 비용 우위 (monthly_savings)
   = 월세금액 - 전세 월 기회비용
   = wolse_amount - (jeonse_deposit - wolse_deposit) * rate / 100 / 12
```

**해석**: `monthly_savings > 0` → 전세 기회비용 < 월세 금액 → **전세 유리**  
**해석**: `monthly_savings < 0` → 전세 기회비용 > 월세 금액 → **월세 유리**  
**해석**: `monthly_savings = 0` → 손익분기

**중요**: 3개 공식 모두 입력 변수(`jeonse_deposit`, `wolse_deposit`, `wolse_amount`, `rate`)만 사용. 다른 출력 키를 참조하지 않음 → App Factory formula dict 규칙 완전 준수.

### 4. 금리/전월세전환율 적용 방식

#### 법적 상한 (주택임대차보호법 제7조의2, 시행령 제9조)

```
법정 상한 = min(한국은행 기준금리 + 연 2%, 연 10%)
```

| 기준 시점 | 한국은행 기준금리 | 법정 상한 |
|---|---|---|
| 2026년 7월 16일 인상 후 | **2.75%** | **4.75%** |

**⚠️ 중요 제약**:
- 법정 상한은 **계약갱신 시 또는 계약기간 내 전환에만** 강제력이 있음
- **신규 계약에는 법적 강제력 없음** (시장 자율)
- 2026년 시장 평균 실거래 전월세전환율: **약 6.4%** (법정 상한과 차이 큼)

#### 계산기 설계 결정 (HOLD)

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 사용자 직접 입력 (권장)** | 신규/갱신 모두 커버, 사용자가 실제 조건 반영 가능 | 기본값 설정 필요 |
| B. 법정 상한 고정 (4.75%) | 단순 | 신규 계약 실거래와 괴리 |
| C. 기본값 제공 + 수정 가능 | 사용성 최적 | 기본값 근거 명시 필요 |

**→ 방식 C 채택 권장**: 사용자 입력 `rate`에 기본값을 제공.  
**→ HOLD**: 기본값을 4.75% (법정 상한)로 할지, 6.4% (시장 평균)로 할지 운영자 결정 필요.

### 5. 손익분기점 계산 가능 여부

#### 두 가지 해석

**해석 A — 전환율 비교 판단 (Tier2 가능)**:
- "내 기회비용 금리 vs 시장 전월세전환율" 비교
- `내 금리 < 전환율` → 전세 유리 / `내 금리 > 전환율` → 월세 유리
- 이 판단은 §3의 `monthly_savings` 공식으로 이미 표현됨 (rate = 내 기회비용 금리로 설정 시)

**해석 B — 기간 기반 손익분기 (Tier1 영역)**:
- "몇 개월 거주하면 전세/월세의 누적 비용이 같아지는가"
- 전제 복잡: 대출 이자 vs 기회비용 vs 자기자금 여부 등
- 기간 = 보증금 차액 ÷ (월비용 차이), 분모 = 0이면 무한대(분기 불가)
- formula dict로 표현 불가: 조건분기 필요

**결론**: 손익분기 "기간" 계산은 이번 Tier2에서 제외. `monthly_savings`의 부호로 유불리를 즉시 판단하는 방식으로 충분.

### 8. App Factory formula dict로 표현 가능한지

**✅ 전부 가능** — 3개 공식 모두 독립 단일 산술식:

```json
{
  "jeonse_opp_cost":       "(jeonse_deposit - wolse_deposit) * rate / 100 / 12",
  "wolse_to_jeonse_equiv": "wolse_deposit + wolse_amount * 1200 / rate",
  "monthly_savings":       "wolse_amount - (jeonse_deposit - wolse_deposit) * rate / 100 / 12"
}
```

**검증**:
- 각 식이 `input_schema` 변수만 참조: `jeonse_deposit`, `wolse_deposit`, `wolse_amount`, `rate` ✅
- 다른 출력 키(`jeonse_opp_cost` 등)를 참조하지 않음: ✅ (App Factory 규칙 준수)
- `formula_engine.validate_formula()` dummy=1.0 통과 여부: ✅
  - 식①: (1-1)*1/100/12 = 0 → OK
  - 식②: 1 + 1*1200/1 = 1201 → OK
  - 식③: 1 - (1-1)*1/100/12 = 1 → OK

**`_compute_js()` 직접 작성 불필요**: App Factory 인라인 HTML(경로 B)로 충분.

### 11. 예외/경계값

| 경계 케이스 | 발생 가능성 | 영향 | 처리 방향 |
|---|---|---|---|
| `rate = 0` | 낮음 (전환율 0%는 비현실적) | `wolse_to_jeonse_equiv`에서 **0으로 나누기** → 런타임 오류 | `rate > 0` 최솟값 검증 필요 (예: 0.1% 이상) |
| `jeonse_deposit < wolse_deposit` | 현실에서 거의 없음 | 음수 기회비용 → 음수 `jeonse_opp_cost` | formula 자체는 정상 동작, UI 해석 주의 문구 필요 |
| `jeonse_deposit = wolse_deposit` | 드물지만 가능 | `jeonse_opp_cost = 0`, `monthly_savings = -wolse_amount` → 항상 전세 유리 | 정상 동작, 의미 있는 결과 |
| `wolse_amount = 0` | 가능 (보증금만 있는 경우) | `monthly_savings = -(jeonse_deposit - wolse_deposit) * rate / 100 / 12` → 항상 음수 | 정상 동작 |
| `rate` 매우 큰 경우 (>100%) | 비현실적 | 수식 오동작 가능성 낮음, 결과값 과대 | 입력 검증으로 상한 설정 권장 (예: 50% 이하) |
| 계약기간 입력 없음 | 현재 설계에서 제외 | 없음 (이번 공식에서 기간 불필요) | 해당 없음 |

**핵심 경계값**: `rate > 0` 강제 필요. 나머지는 formula_engine이 정상 처리.

### 12. 실제 테스트 케이스

공식:
- `jeonse_opp_cost` = `(J - D) * R / 100 / 12`
- `wolse_to_jeonse_equiv` = `D + W * 1200 / R`
- `monthly_savings` = `W - (J - D) * R / 100 / 12`

(J=jeonse_deposit, D=wolse_deposit, W=wolse_amount, R=rate, 모두 만원/%)

| # | 전세보증금(J) | 월세보증금(D) | 월세(W) | 전환율(R) | jeonse_opp_cost | wolse_to_jeonse_equiv | monthly_savings | 판정 |
|---|---|---|---|---|---|---|---|---|
| TC-1 | 30,000 | 5,000 | 80 | 4.75 | **98.96** | **25,211** | **-18.96** | 월세 유리 |
| TC-2 | 30,000 | 5,000 | 100 | 4.75 | 98.96 | **30,263** | **1.04** | 전세 유리 |
| TC-3 | 50,000 | 10,000 | 150 | 5.0 | **166.67** | **46,000** | **-16.67** | 월세 유리 |
| TC-4 | 20,000 | 3,000 | 80 | 4.75 | **67.29** | **23,211** | **12.71** | 전세 유리 |
| TC-5 | 10,000 | 0 | 40 | 4.75 | **39.58** | **10,105** | **0.42** | 전세 유리 (근접) |
| TC-6 (경계) | 20,000 | 20,000 | 60 | 4.75 | **0** | **35,158** | **60** | 전세 유리 (보증금 같음) |
| TC-7 (경계) | 30,000 | 5,000 | 80 | 0 | 오류 | **0으로 나누기** | 오류 | rate=0 검증 필요 |

**TC-1 검증**:
- 전세 기회비용: (30000-5000) × 4.75 / 100 / 12 = 25000 × 0.0475 / 12 = 1187.5 / 12 = **98.96만원/월**
- 월세→전세 환산: 5000 + 80 × 1200 / 4.75 = 5000 + 96000 / 4.75 = 5000 + **20210.5** = **25210.5만원**
- 월 비용 우위: 80 - 98.96 = **-18.96만원** (음수 → 월세 유리)

**TC-5 검증 (순수 전세 vs 순수 월세)**:
- jeonse_opp_cost: 10000 × 4.75 / 100 / 12 = 475 / 12 = **39.58만원/월**
- wolse_to_jeonse_equiv: 0 + 40 × 1200 / 4.75 = 48000 / 4.75 = **10105.3만원**
- monthly_savings: 40 - 39.58 = **+0.42만원** → 전세 유리 (아슬아슬)

## 2. 결론 5가지

---

### ① 계산 공식 확정안

**확정 공식 3개** (출처: 주택임대차보호법 제7조의2 + 한국부동산원 공식 계산기):

```
공식① jeonse_opp_cost       = (jeonse_deposit - wolse_deposit) * rate / 100 / 12
공식② wolse_to_jeonse_equiv  = wolse_deposit + wolse_amount * 1200 / rate
공식③ monthly_savings        = wolse_amount - (jeonse_deposit - wolse_deposit) * rate / 100 / 12
```

**HOLD 항목**:
- `rate` 기본값: 4.75% (법정 상한, 2026년 8월 기준) vs 6.4% (시장 평균) — **운영자 결정 필요**
  - 권장: 4.75% (법정 상한, 근거 명시 가능)
- `rate = 0` 경계값: App Factory 생성 시 프롬프트에 "rate 최솟값 0.1 이상" 지시 필요

---

### ② Tier 최종 판단

**✅ Tier2 유지** (손익분기 기간 계산 제외 조건)

- 3개 공식 모두 단순 사칙연산
- 조건분기 없음 (부호로 판정)
- formula dict로 100% 표현 가능
- 법령 상한을 계산기에 직접 적용하지 않음 (사용자 입력)

단, 아래 기능을 추가하면 즉시 Tier1 재분류:
- 손익분기 기간(개월수) 계산
- 전세자금대출 vs 자기자금 분기 처리
- 세금 혜택 비교(소득공제/세액공제)

---

### ③ formula dict 표현 가능 여부

**✅ 전부 formula dict로 표현 가능**

```json
{
  "jeonse_opp_cost":       "(jeonse_deposit - wolse_deposit) * rate / 100 / 12",
  "wolse_to_jeonse_equiv": "wolse_deposit + wolse_amount * 1200 / rate",
  "monthly_savings":       "wolse_amount - (jeonse_deposit - wolse_deposit) * rate / 100 / 12"
}
```

- `_compute_js()` 직접 작성 불필요
- App Factory 경로 B (WordPress 인라인 HTML) 완전 지원
- `formula_engine.validate_formula()` 통과 (dummy=1.0 검증 완료)

### ④ App Factory 생성 준비 완료 여부
