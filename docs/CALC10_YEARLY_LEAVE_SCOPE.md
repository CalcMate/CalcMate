## 3. 입력값 (input_schema)

| 필드명 | 타입 | 설명 | 검증 |
|--------|------|------|------|
| `years_of_service` | number | 근속연수 (년, 양의 정수) | 1 이상 정수. 소수 입력 시 내림 처리 |
| `used_days` | number | 올해 이미 사용한 연차일수 | 0 이상 정수 |

> **운영자 확인 필요**: `years_of_service`를 정수(int)로만 받을지, 소수(예: 1.5년)도 받을지 — **현재 HOLD**. 정수 입력으로 가정하면 수식 단순화 가능.

## 5. 계산 공식

### 근거

**근로기준법 제60조 (연차 유급휴가)**
- 제1항: 1년간 80% 이상 출근한 근로자 → 15일 유급휴가
- 제4항: 3년 이상 계속 근무 → 최초 1년 초과 매 2년마다 1일 가산, 최대 25일

```
가산 연차 = min(max(0, (years_of_service − 1) ÷ 2), 10)   ← 정수 나눗셈
total_days = 15 + 가산 연차                                  ← 최대 25일
remaining_days = total_days − used_days
```

### Formula dict (App Factory 입력값)

```python
{
    "total_days": "15 + min(max(0, (years_of_service - 1) // 2), 10)",
    "remaining_days": "15 + min(max(0, (years_of_service - 1) // 2), 10) - used_days"
}
```

### Formula Engine 지원 확인 (`modules/formula_engine.py`)

| 연산/함수 | 지원 여부 |
|-----------|----------|
| `//` (정수 나눗셈) | ✅ `ast.FloorDiv` 허용 목록 포함 |
| `min`, `max` | ✅ `_FUNCS` 화이트리스트 등록 |
| `int` | ✅ `_FUNCS` 등록 |
| `if/else` 조건분기 | ❌ 미지원 (범위 제한으로 회피) |

> **`remaining_days` 식에서 `total_days` 변수 참조 불가** — formula_dict의 각 출력 키는 입력변수만 참조할 수 있으므로, `total_days` 계산식을 `remaining_days` 식에 중복 기재한다. 위 formula dict가 이 방식을 사용한다.

## 6. 법적 근거

| 조항 | 내용 |
|------|------|
| 근로기준법 제60조 제1항 | 1년간 소정근로일의 80% 이상 출근한 근로자에게 15일의 유급휴가 |
| 근로기준법 제60조 제4항 | 3년 이상 계속하여 근무한 근로자에게 최초 1년을 초과하는 계속 근무연수 매 2년에 대하여 1일을 가산한 유급휴가; 가산 휴가를 포함한 총 휴가 일수는 25일을 한도로 함 |
| 근로기준법 제60조 제7항 | 제1항·제4항에 따른 휴가는 1년간 행사하지 아니하면 소멸 |

> 이 계산기는 제60조 제2항(1년 미만 근무자 월단위 발생), 제3항(1년차 연차의 다음 해 차감), 단시간 근로자 비례산정(시행령 제26조)을 **적용하지 않는다**.

## 9. HOLD 항목

| # | 항목 | 내용 |
|---|------|------|
| HOLD-1 | `years_of_service` 소수 입력 허용 여부 | 정수만 허용 시 수식 단순. 소수 허용 시 `int()` 감싸기 필요. 운영자 결정 필요 |
| HOLD-2 | `used_days`가 `total_days`를 초과할 때 처리 | `remaining_days`가 음수가 되는 케이스. 화면에서 경고 표시 또는 0으로 클램핑 — App Factory 생성 후 JS 레벨 처리 여부 확인 필요 |
| HOLD-3 | **validate_formula의 min/max 오탐 버그** | `modules/formula_engine.py`의 `validate_formula()`가 AST walk 시 `min`, `max` 함수명을 "input_schema에 없는 변수"로 잘못 판정한다 (False negative). App Factory 생성 시 이 버그가 retry를 유발하고, retry 메시지가 "min/max가 미선언 변수"로 전달되어 AI가 잘못된 공식(25일 cap 누락 등)을 생성할 위험이 있다. `execute_formula()`와 `pre_build_qa Step 6`는 정상 동작하므로 **생성된 계산기의 실행 자체는 문제 없음**. 단, 생성 직후 운영자가 formula 필드를 직접 확인하여 `min(max(0, ...), 10)` 구조가 유지됐는지 검증할 것 |

## 10. 대시보드 운영자 생성 순서 (참고)

```

  → App Factory 탭

              카테고리="노동/고용법", 설명="..."
  → Tier AI 추천 버튼 클릭 → Tier2-A 확인/수정

  → 출력값: total_days, remaining_days
  → Formula dict 입력 (§5 참조)
  → 법적 근거: "근로기준법 제60조 제1항, 제4항"
  → 저장 → HOLD 상태 자동 생성
  → 계산기 관리 탭 → annual-leave-remaining HOLD 항목
  → 🔴 체크리스트 3개 검토·체크
  → READY 전환 버튼 활성화 → READY 전환
  → Build 버튼 → pre_build_qa 6단계 통과 확인
  → _rebuild_site.py 실행 → index/sitemap 반영 확인
  → Git Push → calcmate.kr 배포 확인
```
