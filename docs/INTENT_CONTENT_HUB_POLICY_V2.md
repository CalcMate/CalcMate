# INTENT_CONTENT_HUB_POLICY_V2.md

## 1. 개요
계산기 콘텐츠의 검색 의도(Search Intent) 세분화를 통해 기존 "계산기 1개 = 1개 문서" 구조를 "계산기 중심의 콘텐츠 허브"로 전환하기 위한 운영 정책입니다. 본 문서는 향후 도입할 정책의 설계안을 정의합니다.

## 2. Intent 종류 및 예시
| Intent | 정의 | 예시 제목 |
| :--- | :--- | :--- |
| **계산** | 계산 방법 및 수식 도출 가이드 | "2026 주휴수당 공식 및 자동 계산기 활용 가이드" |
| **자격/조건** | 지급 대상 및 자격요건 세부사항 | "2026 주휴수당 대상자 총정리: 15시간 미만도 가능할까?" |
| **사례** | 실제 상황별 계산 시뮬레이션 | "2026 주휴수당 실제 계산 예시로 쉽게 이해하기" |
| **문제해결** | 미지급 시 대응 및 신고 절차 | "2026 주휴수당 미지급 시 대응법 및 신고 절차 가이드" |
| **제도/법령** | 근거 법령 및 제도적 배경 | "근로기준법으로 보는 주휴수당, 반드시 알아야 할 지급 근거" |
| **FAQ** | 사용자의 궁금증 해결 | "주휴수당에 대해 궁금한 모든 것: 핵심 질문 5가지 답변" |

## 3. Intent별 발행 한도 및 기존 정책 관계
*   **관리단위 변경:** "계산기당 전체 총량"에서 "계산기 + Intent 조합 단위" 관리로 점진적 전환.
*   **기존 정책과의 관계:** `MAX_ARTICLES_PER_CALCULATOR`는 '계산기당 총 발행 상한'으로 유지하되, 현재 3개인 이 값을 Intent 허브 구조 도입 시 12개(6종 Intent × 2개) 수준으로 상향 조정하여 운영할 계획임. (근거: 클러스터형 콘텐츠 운영 시 개별 검색 의도 분산 필요)

## 4. Duplicate 판정 기준 재정의안
*   **현재:** `calculator_id` 단위 중복 판정 (동일 계산기는 제목이 달라도 3개 이상 발행 불가).
*   **변경안:** `(calculator_id, intent_type)` 조합 기반 중복 판정.
*   **전환 기준:** Phase 1(eligibility Intent) 콘텐츠가 기존 메인 콘텐츠와 카니발라이제이션 없이 검색 노출을 점유하는 것을 확인한 후 도입.

## 5. 내부 링크 정책
*   **허브-스포크(Hub & Spoke) 구조:**
    *   **Hub:** 계산기 메인 페이지 (계산 위젯).
    *   **Spoke:** 하위 6종 Intent 문서.
*   **상호 링크:**
    *   모든 Spoke 문서 본문 하단에 Hub로 향하는 링크 배치.
    *   관련된 Spoke 문서 간 상호 링크 배치 (예: '계산' ↔ '사례', '자격' ↔ '제도').

## 6. 업데이트 정책
*   **자동 동기화:** 계산 로직(Core) 변경 시, `ArticleRepository`의 쿼리를 통해 계산기 ID를 포함하는 모든 Intent 문서를 찾아 '최종수정일' 갱신 또는 재평가 플래그(`quality_hold`) 부여.
*   **수동 갱신:** '문제해결(신고 절차)' 등 외부 사실 정보는 주기적인 큐레이션 및 수동 수정 필요.

## 7. 수정 필요 지점 목록 (향후 구현 시)
1.  `modules/calculator_pipeline.py`: `existing_by_calc` 판정 로직에 `intent` 필드 결합.
2.  `repositories/article_repository.py`: `count_active_articles` 조회 시 `intent` 필드 조건 추가.
3.  `modules/collector/calculator.py`: `collect` 함수에서 `intent` 정보를 메타 데이터로 추출.
4.  `main.py`: 파이프라인 호출 시 `intent` 파라미터 매핑 자동화.
