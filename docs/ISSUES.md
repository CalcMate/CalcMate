## 🔴 [상위 이슈] Writer Layer v2 — 출력 안정성(Output Stability) (2026-07-12 승격)

> **롱테일 발행의 진짜 남은 병목은 버그가 아니라 Writer 출력의 회차간 비결정성.**
> G8(⑤)·hold_skip(⑥) 개선을 마친 뒤에도 실업급여 롱테일 3건 발행은 실패(produced 0).
> 원인은 개별 글의 품질 게이트 통과율이 낮고 회차마다 결과가 달라지는 것.

**관찰된 현상:**
- G8 조항 인용 성공률이 키워드마다 들쭉날쭉(같은 계산기여도 "실업급여 계산/조건" 같은 일반형 짧은 키워드는 제40조 누락으로 G8 critical 반복).
- S5 고유성 점수가 동일 계산기에서도 회차별 편차 큼.
- 동일 입력(같은 키워드)도 재시도마다 다른 품질로 나옴(예: "실업급여 계산법"이 어제 2584자 G1실패 ↔ 오늘 2077→2333자 WARN통과).

**확정된 사실 (이번 세션, 커밋 기준):**
- hold_skip 세분화(⑥) 완료·검증됨(커밋 89374e8) — 계산기 단위 과잉 차단 해소. 실업급여 격리 실행에서 hold_skip 6→1, attempted 1→4(다른 키워드 독립 시도 확인). 서명 불변 → 마이그레이션/재평가 영향 없음.
- G8 writer_note 출력지시 패턴(⑤, 커밋 a228633) 자체는 유효하나, 일반형 짧은 키워드에선 여전히 통과율 낮음.
- MAX_ARTICLES_PER_CALCULATOR=3 전역(커밋 361237d). dup/failed는 정상 동작으로 확인(dup=제목중복 게이트 line 373, failed=WP 타임아웃 외부요인 — 새 버그 아님).
- **진짜 남은 병목은 버그가 아니라 Writer 출력의 회차간 비결정성.**

**향후 연구 방향(후보, 미착수):**
- N회 생성 후 Best 선택
- Temperature 정책 조정
- Self-check 단계 추가(생성 직후 결정론 검사 → Gate 前)
- Retry 전략 개선
- 평가 기반 선택(여러 후보 중 게이트 통과 확률 높은 것 선택)

- **개조 내용(원복)**: `KEYWORD_TEMPLATES`에 페르소나·상황 축(계약직/자영업자/프리랜서/50대 재취업/육아퇴사/권고사직/6개월 근무) 추가 + `generate_seo` 프롬프트에 "동의어 반복 금지 + Intent 다양화" 지시.
- **결과**: Persona 다양성은 확보(제목 중복 0 → dup 회피 가능). 단 **Intent는 개별 키워드→개별 제목(1:1) 방식에서 '계산형'에 편중**(유도해도 6/10). Phase 1(배치 생성)에선 질문/사례형까지 나왔음.

## S5(고유정보) — 데이터 밀도와 직접 상관관계 없음 (반증됨)

- **상태**: 관찰 완료. 로직 미수정. Writer Layer v2에서 재검토.
- **결론**: **S5(고유정보) 점수는 registry/legal_master 데이터 밀도와 직접 상관관계가 확인되지 않음(반증).**
- **근거 (2026-07-11 A/B 실험, year-end-tax 한정)**:
  - 국세청·소득세법 교차검증 데이터(deduction_rules 5종 공제 + calculation_flow 7단계)를 legal_master에 넣고 writer 프롬프트에 주입.
  - 본문에 데이터 실제 반영됨(제137조 2회, 공제 5종 모두 언급).
  - 그럼에도 **S5 개별 점수: 30 → 20 (오히려 하락)**. 재현 종합점수 76 → 76(동일).
  - GPT 감점 사유: *"법적 근거 설명이 자연스럽고 계산 예시는 formula와 잘 맞으나, **설명이 가이드 수준을 벗어나지 못해 고유 정보가 적다**."*
  - → GPT는 **정확한 세법 수치도 '일반론/가이드'로 판정**하는 경향. "고유 정보"를 데이터 양이 아니라 '차별적 서술/관점'으로 해석.
- **부수 결과(구분)**: 같은 실험에서 **발행은 성공**(종합 76→81, WARN). 단 이는 S5가 아니라 **S4(문체) 등 다른 점수 상승** 덕분. 즉 데이터 반영이 발행을 도왔으나 S5를 올린 것은 아님.
- **만성성**: 발행된 7종 대부분이 S5 지적을 받음(연차 82/4대 80/실업 81/육아 86/연말정산 81 — 전부 S5 major). S5는 특정 계산기 문제가 아니라 **구조적으로 낮은 항목**.
- **재검토 방향(Writer Layer v2, 로직 미확정)**:
  1. `_score_with_gpt`의 S5 프롬프트 **"고유 정보" 기준 명확화**(무엇이 고유 정보인지 예시 제시).
  2. Prompt Manifest/Self Check에서 S5를 **"차별적 서술" 체크로 분해**.
  3. S5 **가중치/WARN 임계** 재검토(만성적으로 낮으므로 종합점수 왜곡 여부 점검).
- **관련 파일(참고, 미수정)**: `modules/publish_quality.py` `_score_with_gpt` (S5 프롬프트 228행).

## Phase 2-B 종료 기록 (MAX_ARTICLES_PER_CALCULATOR 상향 실험)

- **일시/설정**: 2026-07-12. MAX=3(런타임 주입, config 파일 미변경), 대상=실업급여, 키워드 3개(50대 재취업/6개월 근무/일반).
- **생성 성공**: **0건**. 첫 키워드("50대 재취업 실업급여")가 G8 critical로 3회 REWRITE→품질보류. 나머지 2건은 hold_skip.
- **Gate**: **G8(critical) 실패** — 고용보험법 제40조 조항 미언급(writer가 또 조항 인용 실패, 연말정산/실업급여 재현과 동일 패턴). G1~G7은 도달 전.
- **Score**: 측정 불가 — Gate(G8)에서 막혀 Score 단계 미도달.
- **결론(체크)**:
  - ☑ MAX 상향 dup 회피: **가능**(dup 0 확인 — MAX=3, count 0에서 3건 모두 dup 게이트 통과)
  - ☑ dup 문제 없음
  - ☒ **Gate 영향 있음**(G8 HOLD로 발행 실패)
  - ☑ 회귀 없음(config/KEYWORD 파일 미변경 = 런타임 격리, 7종 무영향)
  - S5: 발행 실패로 측정 안 됨(참고 지표, 합불 미포함 — 오늘 반증한 S5 데이터밀도 가설과 무관)
  - **⇒ 기본값 MAX=1 유지(파일 원본 그대로)**
  - **⇒ 향후 계산기 확대 시 MAX=3 적용은 아래 2개 선결 후 재검토**

- **🔴 신규 발견 2가지 (MAX 상향의 진짜 장애물)**:
  1. **G8 조항 인용 문제가 페르소나 글도 막는다**: legal 무관 페르소나(50대 재취업)라도 실업급여 legal(제40조)은 동일 적용 → writer가 조항을 못 써 G8 HOLD. Writer Layer 개선 전엔 MAX 상향해도 발행 실패.
  2. **`has_quality_hold`가 계산기 단위 → 첫 글 HOLD 시 나머지 hold_skip 연쇄**: MAX=3이어도 한 계산기에서 첫 글이 HOLD되면, 같은 서명으로 나머지 후보가 전부 hold_skip. 즉 "여러 글 발행"이 "모든 글이 Gate 통과"에 의존. MAX>1과 hold_skip 정책이 충돌.

- **⚠️ 운영 교훈**: 실험 중 시트 기존행을 임시 비활성했는데, 원복 시 Sheets 연결 오류(RemoteDisconnected)로 원복이 1차 실패 → 수동 재시도로 복원함. 프로덕션 시트를 조작하는 실험은 **원복에 재시도 로직 필수**.

- **백로그(Writer Layer v2 / Prompt Builder 논의 시 재검토)**:
  - Intent 편중 근본 해결(배치 생성 전환 / Intent 키워드 내포)
  - G8 조항 인용 강제(writer가 제N조를 실제로 쓰게)
  - `has_quality_hold` 계산기 단위 hold_skip을 MAX>1과 양립하도록 재설계(예: 키워드/글 단위 HOLD)
