**[확정] 단축 이력과 현재 적용 여부**

|---|---|---|---|

계산기는 현행 기준(2020-06-01 이후)만 구현하면 충분.

**[HOLD-1] 전역일 정확한 계산식**

가장 일반적으로 사용되는 방식:
```
전역일 = 입대일 + 복무개월 - 1일
예: 2025-06-01 입대, 18개월 → 2026-12-01 - 1일 = 2026-11-30
```

그러나 **병무청 공식 계산 기준이 이 방식인지 직접 확인 필요**.
공식 출처가 확보되기 전까지 HOLD. 위 방식을 잠정 채택하되 명시적으로 고지.

관련 변수: 윤년(2월 28/29일), 월말(1월 31일 + 1개월 = 2월 28/29일)은
`relativedelta` 계산 시 자동 처리됨. 예: 2025-01-31 + 1개월 = 2025-02-28.

### §4. 날짜 계산 방식

**달력월(calendar month) 기준** vs **정확한 일수** 비교:

| 방식 | 설명 | 병무청 기준 여부 |
|---|---|---|
| 달력월 기준 | `enlistment_date + relativedelta(months=N) - 1일` | 추정 (HOLD) |
| 정확한 일수 | `enlistment_date + N×30.4375일` | 아닌 것으로 추정 |
| 정확한 일수 v2 | `enlistment_date + 548일(18개월×30.44...)` | 사용 안 함 |

→ 달력월 기준이 자연스럽고, 군에서 "18개월"로 발표하므로 달력월 채택.
단, 공식 출처 확보 필요 (HOLD-1).

**경계 케이스:**

| 케이스 | 처리 방식 |
|---|---|
| 1월 31일 입대 + 1개월 | `relativedelta` → 2월 28일(윤년 아닌 경우) |
| 12월 31일 입대 + 18개월 | 2026-06-30 |
| 윤년 2월 29일 입대 | 실제로는 발생(예: 2024-02-29), +18개월 → 2025-08-28 |

### §7. App Factory formula/date 처리 가능 여부

**핵심 발견: 3가지 경로 검토**

#### 경로 A: formula dict 방식 — **불가**

`formula_engine`은 `min/max/round/abs/int/float` + 사칙연산만 허용.
날짜 덧셈(`입대일 + 18개월`)은 JS `Date` 객체 조작이 필요하며 산술식으로 표현 불가.

```python
# formula_engine 허용 함수
_FUNCS = {"min": min, "max": max, "round": round, "abs": abs, "int": int, "float": float}
# → datetime, relativedelta, Date() 전부 불가
```

#### 경로 B: date_based compute_type 재활용 — **불가**

`app_generator._compute_js()` date_based 분기는 `start_date`/`end_date` 하드코딩:
```python
# app_generator.py:783
'  var s = new Date(inputs["start_date"]); var e = new Date(inputs["end_date"]);\n'
'  var total_days = Math.floor((e - s) / (1000*60*60*24));\n'
```
군인 계산기 구조:
- 입력: `enlistment_date`(입대일) + `branch`(병종)
- `end_date`(전역일)는 **출력**, 입력이 아님
- `date_based` 패턴과 구조적으로 불일치

또한 `_form_fields_v2()`는 `type="date"` 또는 `type="number"` 만 지원 — `<select>` 미지원.
병종 선택 드롭다운을 자동 생성 불가.

```python
# app_generator.py:_form_fields_v2
if "date" in str(spec).lower():
    # → <input type="date">
else:
    # → <input type="text" inputmode="numeric">  ← select 없음
```

#### 경로 C: HTML inline 방식 (App Factory 경로 B) — **가능**

전세vs월세 계산기(`_save_jeonse_calculator.py`)와 동일하게, 완전한 자체 HTML+JS를
`app["html"]` 필드에 직접 제공하면 App Factory save_app()이 DB에 저장.
이 방식으로:
- `<select id="branch">` 드롭다운 가능
- `<input type="date" id="enlistment_date">` 가능
- JS에서 `new Date()` + `relativedelta` 상당 로직 직접 구현 가능

**단, 이 방식은 App Factory의 자동생성(AI 프롬프트) 경로가 아닌 수동 HTML 작성**.
전세vs월세와 동일하게 계산 로직 직접 구현 → `_formula_valid: True, _formula_msg: "OK"`로 수동 세팅.

**결론**: formula dict/date_based 자동생성 불가. HTML inline 수동 작성 후 App Factory 저장 경로 사용.

- v3 `_CATEGORY_AF_YAML_MAP`에 `"국방/병역": "defense_af"` 추가 필요
  (또는 기존 카테고리 재분류 가능하나, 별도 카테고리 권장)

| 법령 조건분기 | 없음 (복무기간은 병종 선택 입력값으로 고정) |
| 날짜 경계처리 | `relativedelta` 표준 처리로 충분 |
| legal 검증 필요도 | 복무기간 수치는 법령 명시, 추가 검증 불필요 |

단, 아래 기능 추가 시 Tier1 재분류:
- 전역 연장/단축 이벤트(영창, 포상휴가 등) 반영
- 진급 예정일 계산 (계급별 진급 소요기간 법령 참조 필요)
- 조기 전역/입영 연기 조건 처리

### ③ App Factory 표현 가능 여부

**❌ formula dict / date_based 자동생성 불가**
**✅ HTML inline 방식(경로 B)으로 가능**

| 방식 | 가능 여부 | 이유 |
|---|---|---|
| formula dict | ❌ | `formula_engine`은 산술 전용, `Date()` 연산 불가 |
| date_based 재활용 | ❌ | `start_date`/`end_date` 하드코딩, `<select>` 미지원 |
| HTML inline (App Factory 경로 B) | ✅ | 전세vs월세와 동일 방식 가능 |

**HTML inline 방식 구현 요소:**
- `<input type="date" id="enlistment_date">` → 기존 패턴 재사용
- `<select id="branch">` → 5가지 병종 선택
- JS: `new Date(enlistmentDate)`, `setMonth(m.getMonth()+months)`, 전날 계산

**제약사항:**
- `_compute_js()` 기반 정적 사이트 생성과 연계 불가 (별도 설계 필요)
- formula dict가 없으므로 `validate_formula()`는 수동으로 `_formula_valid: True` 세팅
- `generate_calculator()`의 date_based 분기가 작동하지 않음 → 정적 사이트 페이지 생성을 위해 HTML을 `_site/` 디렉토리에 직접 배치하는 별도 처리 또는 HTML inline 방식으로만 운영

## 부록: App Factory 재사용성 검증 시사점

이번 조사로 드러난 **App Factory 경로 B(HTML inline) 재사용 한계**:

| 항목 | 전세vs월세 | 군인 전역일 |
|---|---|---|
| formula dict 사용 가능 | ✅ | ❌ |
| `_compute_js()` 자동생성 | ✅ (dict 경로) | ❌ (Date 연산 불가) |
| `<select>` 입력 | 없음 (숫자만) | 필요 |
| HTML inline 경로 | ✅ | ✅ |
| 정적 사이트 generate_calculator() | ✅ | ❌ (별도 처리 필요) |

**"Tier2 신규 계산기 표준 경로 확정" 판단 기준 수정 필요**:
- formula dict(산술식)만으로 표현 가능한 Tier2 → 표준 경로 확정 가능
- 날짜 연산이 포함된 Tier2 → HTML inline 방식 + 정적 사이트 연계 별도 설계 필요
- 즉, "Tier2 표준 경로"는 계산 유형(산술 vs 날짜)으로 세분화해야 함
